# Design

## Context

MediaHub 当前采用 Electron 三段式结构：主进程负责库、扫描、协议和 SQLite，preload 暴露窄 API，渲染层用 zustand 管理界面。库已迁移到 `.mediahub/library.db`，迁移失败时仍可能使用全局回退库；`media://` 负责库内文件读取，缩略图缓存位于 `.mediahub/thumbs`。

现有规格已经覆盖了大部分目标行为，但实现与规格之间有缺口。`docs/缺陷分析报告-架构评审.md` 记录的数据库迁移 S0-4 仍未修复；当前工作区还包含未提交的筛选条视觉改动，恢复统计时需要保留这些视觉调整，只恢复被删掉的数据展示与分隔结构。

## Goals / Non-Goals

**Goals:**

- 关闭可被渲染层触发的路径越界、任意建库和旧库清空入口。
- 保证全局回退库、批量移动、数据库迁移和 Eagle 导入不会造成串库或元数据损坏。
- 让大库扫描、视频探测和 3D 首屏加载在真实负载下可接受。
- 让筛选条、空态、灯箱、检查器和偏好设置重新与现有规格一致。
- 删除确认无引用的演示数据与依赖，减少首屏体积。
- 清除依赖审计中的高危项，并让原生模块同时适配 Node 与 Electron 44。

**Non-Goals:**

- 不重写 Electron IPC 架构，不引入新的状态管理或数据库框架。
- 不改变素材库目录格式、缩略图文件命名或用户已有数据的存储位置。
- 不新增同步、云存储、标签管理或 3D 编辑功能。
- 不为已删除的“索引外部目录”概念恢复任何入口。

## Decisions

### 1. 建库路径只接受主进程选择结果

主进程在 `dialog:pickFolder` 成功时把真实目录加入一个短期允许集合；`library:create` 只接受该集合中的路径。创建前再用 `realpath` 和 `stat` 确认是目录，并拒绝磁盘根。这样合法用户流程不变，渲染层无法通过伪造 IPC 参数把 `C:\` 或系统目录绑定为库。替代方案是只做 `realpath`，但那仍允许任意目录，无法满足现有安全边界。

### 2. 缩略图参数先校验再拼路径

`media://` 的缩略图 `v` 参数只接受 20 位小写/大写十六进制指纹，校验发生在 `thumbPath` 之前。非法值直接返回 403，不进入缓存清单或后台生成。Range 解析同时改为标准语义：`bytes=-N` 表示最后 N 字节，起止倒置返回 416。这样协议路径和视频拖动都只有一套可验证规则。

### 3. 回退库的写操作统一带 `library_id`

把 `updateAsset`、`addTag`、`removeTag` 的库作用域下沉到 store 层：更新和删除都带 `library_id` 条件，查不到当前库对应素材时不写库。调用方传入 `libraryId`，避免 handler 只做一次前置检查后仍调用无作用域的写函数。替代方案是只在 IPC 层查一次，但那会留下其它内部调用点继续绕过隔离。

### 4. 旧库清空从渲染层移除

`legacyStats` 与 `purgeLegacy` 没有被界面使用，直接从 preload API 和 IPC 注册中删除。旧全局数据继续保留，库正常使用库内数据库；未来若需要清理，只能由主进程维护流程带原生确认执行。这样删除的是未使用的危险入口，不引入新的 UI。

### 5. 数据库迁移做到可重放

每个 schema 步进把 DDL 和 `PRAGMA user_version` 放进同一个事务；所有 `ALTER TABLE` 先查 `table_info`，已存在就跳过。迁移失败时保持原版本，下一次启动可以安全重放。替代方案是只加事务，但如果事务提交后版本写入失败，仍会重复 ALTER，因此必须同时做幂等检查。

### 6. 批量移动按“成功子集”落库

磁盘重命名仍逐个执行。每成功一项就记录新路径；遇到失败时，只把已成功项放入数据库事务并更新缩略图清单，返回真实 `moved` 数量，然后让渲染层重新加载。这样部分成功不会变成“磁盘已移动、数据库仍指向旧路径”。失败项保持原位置，符合现有 `asset-browser` 规格。

### 7. 检查器输入框按素材 id 重置

备注和来源链接保持当前的非受控输入方式，但给控件加 `key={a.id}`，切换素材时重新挂载并采用新的 `defaultValue`。这比引入两套本地草稿状态更小，也不会改变失焦保存语义。测试通过开发调试桥验证 A→B 切换后输入值不串。

### 8. Eagle 导入改为复制

把 Eagle 导入的 `moveFile` 改为“复制到目标、目标确认存在后再登记数据库”，源文件不删除。复制阶段失败时清理已复制的目标文件并回滚数据库写入。用户明确选择迁移时才使用移动语义；当前“导入 Eagle 素材”入口保持导入含义。

### 9. 视频探测和扫描并发分开

`probeVideo` 改为只执行 `ffmpeg -i <file>` 读取 stderr，不添加 `-f null -`。扫描仍可并发处理图片，但视频探测单独经过一个并发信号量，上限 4，避免同时启动数百个 ffmpeg。扫描批次大小保持不变，避免改变现有图片扫描速度。

### 10. 扫描按批次入库

`scanLibrary` 增加可选的批次回调；`scanLibraryContents` 在每批扫描完成后调用 `upsertScanned` 并发送带 id 的增量事件。`reconcileRoot` 继续收集完整集合用于缺失对账，不改变启动对账语义。这样扫描中网格可以逐步出现素材，且不会把全部条目长期留在内存。

### 11. 界面状态按当前视图收敛

筛选条重新订阅 `assets`，用 `queryAssets` 和 `statsOf` 计算筛选/选中统计；标签下拉改为接收当前素材数组。空态根据搜索、筛选和颜色筛选判断是否进入“结果为空”，回收站空态增加返回全部素材。灯箱翻页复用 `queryAssets`，如果当前素材不在筛选集合中才回退到全部未删除素材。

### 12. 偏好和快捷键只保留真实能力

删除 `hoverAudio`、`hoverGif` 和未实现的 `openMode`，保留主题、自动启动、关闭行为、自动同步、视频悬停和悬停音量。`Ctrl+C` 通过一个共享的“复制当前选择”动作实现，由全局快捷键和右键菜单共同调用；没有选择时不拦截系统复制。

### 13. 3D 运行时按需加载

把 `Viewer3D` 改为动态导入，Card 和 Lightbox 都通过 `React.lazy` + `Suspense` 使用。图片库首屏不再加载 Three.js 与模型加载器。GLTF/FBX 解析传入原文件所在目录作为 base URL，使外部 `.bin` 和贴图可以解析；GLB/GLTF/FBX/OBJ 加载失败统一回退占位舞台。只保留 WebAssembly 版 Draco 资源，删除不再需要的 asm.js 回退。

### 14. 删除无效数据而不是保留兼容展示

`dataset.ts` 只保留 `TAGS` 和 `SUGGESTED_TAGS`；删除 `ASSETS`、`FOLDERS`、`COLOR_STRIP`、硬编码路径和演示辅助函数。删除 `lucide-static` 依赖。`statsOf` 在恢复筛选统计后继续使用，不删除。

### 15. 原生依赖升级到 N-API 预编译模型

Electron 升到 44，构建链同步升级到 electron-vite 6 / Vite 8；chokidar 5 是 ESM-only，因此打进主进程 bundle。`better-sqlite3` 13 自带跨运行时 N-API 预编译绑定，不再按 Electron ABI 复制双份二进制，删除 `@electron/rebuild` 与旧双 ABI 脚本。`sharp` 升到修复高危公告的 0.35.5，并在 Electron 与 Vitest 两个运行时分别验证。这样既消除漏洞，也移除不再需要的原生编译流程。

## Risks / Trade-offs

- **Eagle 复制会占用双倍磁盘空间** → 导入前显示进度，复制失败清理目标；不删除源库，用户可自行清理。
- **建库白名单会阻止脚本化直接调用** → 测试和开发工具也必须先走 `pickFolder`，或在主进程注入测试允许路径。
- **绑定 `library_id` 会改变内部函数签名** → 用 TypeScript 编译错误逐个更新所有调用点，并补跨库 id 测试。
- **扫描按批入库会增加数据库事务次数** → 每批一次事务，渲染层继续按帧合并事件，避免逐条重渲染。
- **删除 asm.js Draco 回退会让极旧环境无法解码** → 目标 Electron 44 已支持 WebAssembly；失败时仍回退占位舞台，不崩溃。
- **3D 懒加载会多一次网络/模块加载** → 只影响首次打开 3D 素材，用加载占位和进度提示覆盖等待。
- **major 依赖升级可能改变打包或原生加载行为** → 以类型检查、全量测试、生产构建、Electron 调试桥和 `sharp` / SQLite 冒烟共同验收。

## Migration Plan

1. 先上数据库迁移幂等与事务修复，确保已有用户数据在升级时可重放。
2. 移除旧库清空 preload API，保留已有全局数据，不做自动删除。
3. 建库路径白名单和缩略图参数校验随主进程一起发布；旧缓存目录无需迁移。
4. 批量移动、Eagle 复制、扫描分批属于运行时修复，不需要数据迁移。
5. 删除演示数据和依赖后重新构建，确认 `out/` 不进入版本控制。
6. 回滚策略：数据库迁移只新增列且幂等，可回退到旧版本读取；Eagle 复制保留源文件，失败可重试；旧库清空 API 删除后不影响已存在数据。
7. 依赖升级随同本轮发布；旧双 ABI 二进制无需迁移，重新安装后由 N-API 预编译包直接加载。
