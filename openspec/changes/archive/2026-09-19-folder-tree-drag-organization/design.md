## Context

见 `proposal.md`。当前侧栏已把本地目录标记为可拖动，并将拖至行的上/下半部解释为前后排序；但“成为子文件夹”依赖行右侧 30% 的隐式命中区。主进程已有受限的目录移动、路径重命名、素材归属同步和 `folder_orders` 写入，不能绕开这条链路。

## Goals / Non-Goals

**Goals:**

- 用完整行的上、中、下垂直区域表达排序或移入的结果，使用户无需猜测横向阈值。
- 让拖放反馈与最终动作一一对应，并保持导航重映射和刷新行为。
- 保持真实磁盘目录、索引/Eagle 只读节点及已有目录安全校验的边界。

**Non-Goals:**

- 不新增右键菜单、键盘移动命令、多选文件夹拖动或跨素材库移动。
- 不修改目录重命名、新建、素材拖入目录或索引目录浏览的交互。
- 不改动主进程 IPC 参数、数据库 schema、`folder_orders` 格式或文件监听机制。

## Decisions

### 三段垂直投放区取代右侧阈值

文件夹目标行按垂直方向划分为上方、中间、下方三个稳定区域：上方映射 `before`、中间映射 `inside`、下方映射 `after`。拖入子级不再取决于横向坐标，窄侧栏和不同文本长度下的结果保持一致。

备选方案是保留“右侧区域移入”的规则；它减少改动，但没有可发现性，且用户拖至标签文字时会得到与视觉预期不同的排序结果，故不采用。

### 以同一个投放结果驱动反馈和提交

拖过目标行时只计算一次放置结果并写入 ref，同时直接切换目标行的投放 class；放下时读取同一个 ref 调用现有 `moveFolder(source, target, placement)`，避免每次 `dragover` 触发递归树重渲染，也避免 `onDrop` 再次从坐标推导造成反馈与最终结果不一致。

上方和下方继续使用插入线；中间使用整行高亮，并让折叠/展开、计数与文字仍可辨认。投放 class 不使用过渡动画，确保同一 `dragover` 事件周期内出现反馈。无效目标不写入投放状态，因此不显示可放置反馈。

备选方案是为三种结果增加额外悬浮菜单或确认对话；目录拖拽是高频本地整理操作，已有安全校验和即时刷新，额外交互会增加步骤，故不采用。

### 复用现有受限移动和顺序持久化链路

渲染层只调整命中判断和反馈；实际移动仍经既有 `folders:move`。前后投放保留同级顺序更新，中间投放保留真实目录移动及其对子目录、素材数据库路径和排序记录的同步。根目录回退不属于当前交互。

### 放下后先更新本地树，再由主进程校准

放下可接受文件夹后，渲染层按与主进程相同的移动块规则立即重写文件夹路径、同级顺序、当前导航和素材目录链，不等待 `folders:move` 返回。IPC 仍负责真实磁盘移动、数据库同步和最终路径确认；成功后重新加载权威数据，失败则提示并重新读取真实目录，避免乐观状态覆盖实际错误。

备选方案是仅在渲染层重排树节点；刷新后会丢失顺序，也无法产生真实父子目录，故不采用。

### 以纯函数覆盖投放语义，以服务测试覆盖磁盘结果

将行命中规则提取为不依赖 DOM 的小型纯函数，供拖过与放下共用，并在现有 Vitest 测试中覆盖三段结果、同级无效投放和后代循环保护。保留已有文件系统测试，验证中间投放会实际移动整个目录树且排序在重新列举时保持。

备选方案是只做人工拖拽验收；坐标边界容易回归，纯函数测试成本更低，故不采用。

### 素材拖入使用同步 DOM 高亮

素材拖拽经过文件夹行时只切换当前目标行的 `drop-target` class，不把每个 `dragover` 转成 React state 更新；放下或离开目标时清理 class，避免高频拖拽事件触发侧栏整棵树重渲染。

## Risks / Trade-offs

- [行高较小导致拖拽时误入中间区] → 上下插入区保持清晰比例和插入线，拖入反馈只在中间区出现；实际尺寸在 Electron 中人工复验。
- [折叠父目录后拖入] → 目标行仍可作为中间投放目标，移动后维持用户原有折叠状态，不自动展开无关节点。
- [文件系统移动或数据库同步失败] → 继续由现有 IPC 返回错误，并通过重新加载活动素材库恢复树的真实状态。
- [拖动到只读 Eagle/索引节点] → 渲染层拒绝投放，主进程仍保留仅允许本地真实目录的校验。

## Migration Plan

无需数据迁移。发布后，已有目录和 `folder_orders` 记录继续生效；回滚仅恢复旧的侧栏拖放命中与样式，不会改变已保存的目录结构或排序数据。
