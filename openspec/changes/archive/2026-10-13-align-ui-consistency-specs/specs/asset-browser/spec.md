# Spec Delta

## MODIFIED Requirements

### Requirement: 筛选条
筛选条(42px)SHALL 从左到右包含:颜色构造按钮(彩虹圆球,展开时蓝描边)、五个筛选下拉按钮(格式/形状/尺寸/评分/标签,内容按规格;有激活筛选的按钮呈 .on 蓝底蓝字)、竖分隔线、结果统计(「筛选结果 N 项 · 大小」,数字加粗)、视图下拉(图标随视图切换)、竖分隔线、缩放滑块(88×3px 轨道,拖动实时改 --colw 170–320px 并刷新填充比例)、面板开关(隐藏检查器时按钮进入 .on 态)。筛选组与其后计数之间 SHALL 有一条竖分隔线,把剩余空间顶开的 `margin-left:auto` SHALL 落在这条分隔线上,SHALL NOT 落在结果统计上——否则分隔线会被留在筛选组一侧、与计数分家,计数重新变成一句悬空注释。格式下拉 SHALL 含「CSS」项,选中后仅显示 CSS 素材;形状、尺寸、评分筛选对 CSS 素材 SHALL 按无尺寸素材的既有语义处理,不得使 CSS 素材在该筛选下意外全部消失或全部出现。

#### Scenario: 拖动缩放滑块
- **WHEN** 用户拖动缩放滑块
- **THEN** 素材缩略图列宽在 170–320px 间实时变化,轨道蓝填充比例同步刷新

#### Scenario: 按 CSS 格式筛选
- **WHEN** 用户在格式下拉选择「CSS」
- **THEN** 结果统计与网格只保留 CSS 素材,其它格式不出现在该视图中

#### Scenario: 筛选组与计数各自成组
- **WHEN** 用户改变窗口宽度或切换缩放滑块
- **THEN** 筛选组保持靠左、结果计数保持靠右,两者之间的竖分隔线跟着计数一起移动,分隔线不会停留在筛选组一侧

### Requirement: 三视图切换
素材网格 SHALL 支持三种视图:瀑布流(默认,CSS 多列 column-width:var(--colw))、网格(repeat(auto-fill,minmax(var(--colw),1fr)),缩略图统一 4:3)、列表(单列行,列网格 96px|1.7fr|52px|92px|76px|60px|96px|34px,含粘性表头,行悬停玻璃底,无评分列)。视图下拉切换时容器类与按钮图标同步切换。瀑布流 SHALL 是唯一使用素材展示比例的视图:其列内定位高度 SHALL 与卡片实际渲染比例同源(同一 `thumbRatio` 求值),SHALL NOT 在估算侧与渲染侧各做一份比例计算;网格视图缩略图统一 4:3,列表视图固定 96x58,两者 SHALL NOT 受素材原始比例影响。此处「统一 4:3 / 固定 96x58」约束的是缩略图**容器**的几何尺寸;容器之内的素材填充方式(cover 或 contain)由「素材卡片」要求规定,不受本条约束。

#### Scenario: 切换到列表视图
- **WHEN** 用户在视图下拉中选择「列表」
- **THEN** 网格切换为单列行布局并显示表头(缩略图/文件名/类型/分辨率/大小/时长/导入时间/操作),按钮图标变为列表图标

#### Scenario: 瀑布流列内定位与卡片一致
- **WHEN** 瀑布流中含极端宽高比素材且素材总数超过 500 项(启用虚拟化)
- **THEN** 同列卡片按序紧密排列,相邻卡间隙在几像素内,不出现卡片重叠或列底空档

#### Scenario: 网格视图容器比例不随素材变化
- **WHEN** 用户在网格视图中浏览一张 1200x172 的超宽素材
- **THEN** 缩略图容器仍为 4:3,单元格尺寸与相邻普通素材一致,不因该素材的原始比例改变容器几何

### Requirement: 素材卡片
卡片(figure 语义)SHALL 包含:缩略图、左下类型徽章(深色玻璃小条,视频/三维格式带彩色圆点,映射按规格第 10 节)、右下时长徽章(仅视频)、右上唯一快捷操作收藏(悬停出现)、视频中央播放钮与底部进度条(悬停出现)、三维模型 CSS 转台立方体(六面半透明蓝玻璃 18s 自转 + 底部椭圆投影)、名称一行截断与元信息(分辨率  大小;3D 为「面数  大小」)。缩略图 SHALL 按素材比例展示,比例收敛到 `[1/2, 21/9]`(`MIN_THUMB_AR` 与 `MAX_THUMB_AR`):界内比例如实展示,超出部分交给 `object-fit:cover` 居中裁切,无尺寸素材按 4:3 兜底。原始比例超过 `MAX_THUMB_AR` 的素材 SHALL 例外改用 `object-fit:contain` 整条展示,判定 SHALL 以「素材原始比例 > `MAX_THUMB_AR`」为依据、SHALL 在瀑布流与网格视图中生效、SHALL NOT 在列表视图生效(列表缩略图是固定 96x58 的小图,本就该 cover);留白虽不完美,但细长条素材整条可辨比只留中段更接近真相。缩略图 SHALL NOT 因悬停改变宽高或位置。元信息行 SHALL 使用二级文本色 `--t2`,网格与列表两种视图取值一致。收藏按钮 SHALL 在夜间主题下满足 WCAG AA:白图标对按钮底对比度  4.5:1;已收藏态 SHALL 同时以实心图标与更深底色表达,SHALL NOT 仅依靠颜色区分状态。卡片外框圆角 SHALL 比现有卡片令牌小 5px,且 SHALL NOT 显示外部投影;卡片和缩略图 SHALL NOT 因悬停产生位移或缩放。【禁止】卡片缩略图显示中央转台角标、复选圈、快速预览按钮、更多按钮、文件后缀与星级。选中态为蓝描边且不引入外部投影。

#### Scenario: 视频卡片悬停
- **WHEN** 用户悬停视频卡片
- **THEN** 卡片与缩略图位置和尺寸不变,播放钮、进度条和收藏按钮出现;复选圈、快速预览按钮与更多按钮不可见

#### Scenario: 三维卡片悬停
- **WHEN** 用户悬停 GLB 或其他三维素材卡片
- **THEN** CSS 转台立方体继续自转,缩略图中央不出现转台预览角标

#### Scenario: 单击多选
- **WHEN** 用户依次单击两张卡片(均无修饰键)
- **THEN** 前一张取消选中、后一张成为唯一选中项(检查器与键盘焦点随之切换);多选改用 Shift(区间)与 Ctrl/Cmd(逐张)

#### Scenario: Shift 区间选
- **WHEN** 用户先单击卡片 A,再按住 Shift 单击卡片 B
- **THEN** A 到 B(含端点,按当前视图顺序)全部进入选中态并替换此前选区;继续 Shift+单击卡片 C 时区间改为 A 到 C

#### Scenario: Ctrl 逐张切换
- **WHEN** 用户按住 Ctrl(macOS 为 Cmd)单击一张未选中的卡片
- **THEN** 该卡片追加选中且其它卡片保持不变;再次 Ctrl+单击同一卡片则取消该卡选中

#### Scenario: 右键自选中
- **WHEN** 用户在未选中的卡片上点右键
- **THEN** 该卡片成为唯一选中项(检查器切到它)并弹出菜单;在已选中项之一上点右键时保留整组选中不变

#### Scenario: CSS 卡片显示渲染缩略图
- **WHEN** 用户浏览含 CSS 素材的文件夹
- **THEN** CSS 卡片显示该样式渲染效果的缩略图与 CSS 徽章,元信息只显示大小,不出现分辨率占位

#### Scenario: 极端比例缩略图收敛
- **WHEN** 用户浏览一张 1200x172(约 7:1)的视频素材卡片
- **THEN** 缩略图容器按 21:9 展示(232px 列宽下高度不低于 90px),容器内素材按 `contain` 整条可见、不只剩中段,不再塌成一条横线;瀑布流列内占位与卡片实际高度一致,同列卡片不重叠

#### Scenario: 界内比例仍按 cover 裁切
- **WHEN** 用户浏览一张比例在 `[1/2, 21/9]` 区间内的素材(如 16:9 视频)
- **THEN** 缩略图仍走 `object-fit:cover` 居中裁切,不出现留白,与该素材改动前的外观一致

#### Scenario: 竖屏素材不被误裁
- **WHEN** 用户浏览一张 9:16 的竖屏素材(比例 0.5625)
- **THEN** 缩略图完整按 0.5625 展示,不触发裁切;超过下界 1/2 的更瘦截图才按 1/2 裁切

#### Scenario: 收藏状态双通道可辨
- **WHEN** 用户在夜间主题下把一张卡片加入收藏(悬停揭示收藏按钮)
- **THEN** 按钮底色加深、图标由描边变为实心,白图标对比度不低于 4.5:1、已收藏粉心不低于 3:1,在灰度下也能分辨两种状态

#### Scenario: 卡片视觉清理
- **WHEN** 用户浏览任意素材卡片
- **THEN** 卡片外框没有投影,圆角为卡片令牌减 5px,悬停无位移或缩放;除收藏外没有缩略图角标快捷操作
