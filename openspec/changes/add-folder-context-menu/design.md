# Design

## Context

文件夹树由 `Sidebar.tsx` 从真实目录和当前库资产计数构建。现有文件夹操作已经集中在 `services/folders.ts` 与 `folders:*` IPC；素材右键菜单是独立组件，不应把文件夹目标、层级移动和删除确认塞进素材选中集语义。

## Goals / Non-Goals

**Goals:**

- 右键目标始终是鼠标下的真实文件夹，不受当前素材选中集影响。
- 所有路径动作先经库根校验，再访问磁盘。
- 删除先完成系统回收站移动，再清理数据库，避免“索引已删但文件还在”的不可恢复状态。
- 菜单具备新入口、子菜单、屏边翻转、键盘 Esc 关闭和 reduced-motion 降级。

**Non-Goals:**

- 不增加永久删除选项。
- 不改动素材右键菜单的动作集合。
- 不新增依赖或第二套菜单框架。
- 不把右键菜单状态持久化；它是瞬时交互状态。

## Decisions

### 1. 独立文件夹菜单组件

新增 `FolderContextMenu.tsx` 和 `folderCtxMenu` 状态。素材菜单与文件夹菜单互斥，但各自保留关闭动画、定位和子菜单逻辑，避免把两套不同目标模型塞进一个组件。

替代方案是扩展 `ContextMenu.tsx` 的 `assetId` 联合类型。该方案会让素材选中、文件夹路径、导出和删除确认共享一套条件分支，回归面大于新增一个小组件。

### 2. 创建子目录复用文件夹服务

`createLibraryFolder(root, parentPath)` 校验父路径位于库内且真实存在，然后在父目录中寻找唯一的 `未命名` 名称。IPC 将新路径插入父级子树之后并持久化顺序；渲染层展开父级、选中新节点并进入现有内联重命名。

### 3. 移动子菜单只列出合法目标

候选目标由 `canDropFolder(source, target, 'inside', true)` 生成。该函数已经排除自身、后代与当前父目录，因此右键菜单和拖拽共享同一合法性定义。

### 4. 打开源目录走最小权限 IPC

主进程先确认相对路径存在于 `listLibraryFolders` 的物理目录列表，再用 `resolveLibraryFolder` 解析真实路径并拒绝越界。随后 `shell.openPath` 打开目录本身，而不是只在父目录中选中。

### 5. 删除以回收站为提交点

处理顺序固定为：

1. 校验相对路径属于当前库的真实文件夹。
2. 暂停根目录 watcher。
3. `shell.trashItem(realPath)` 将整棵目录移入系统回收站。
4. 在同一数据库事务中删除该前缀下的资产行、级联标签关联和 `folder_orders`。
5. 清理不再被存活素材引用的缩略图和文档预览缓存。
6. 广播 `assets:changed` 并让渲染层回读权威状态。

若第 3 步失败，数据库完全不动。若第 3 步成功但后续索引事务失败，操作返回错误并回读，磁盘事实仍是回收站中的目录，不会出现伪造的成功。

### 6. Uiverse 组件只借交互语法

采用 Uiverse 菜单组件的分组列表、图标槽、组间分隔、悬停微位移和危险项独立配色。表面、圆角、字号、高度、动效时长、浅色与夜间颜色全部映射到项目 `glass-menu` 和 `tokens.css`，不复制组件固定深色值。

## Risks / Trade-offs

- `shell.trashItem` 的行为由系统回收站策略决定；不可用或失败时明确报错，不降级为永久删除。
- 删除目录会移除其下素材的库内标签、评分与备注记录，符合目录整体移除语义；确认文案必须写清这一点。
- 子菜单目标较多时需要滚动，沿用现有 `max-height` 与底部渐隐线索。

## Migration

无数据迁移。新 IPC 与 UI 状态均为增量能力；旧目录顺序记录在原位置继续生效。
