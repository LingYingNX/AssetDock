## Why

三个实际使用问题:①几万素材全量渲染 DOM 必卡;②库的元数据存在应用全局目录,素材文件夹拷走不带配置,不符合"库即文件夹"的直觉;③用户素材常常分散在不能移动的目录(客户盘、工程目录),需要不移动文件就能纳入当前库浏览。

## What Changes

- **库内配置与数据**:`<素材库>/.mediahub/library.db`(SQLite)+ `.mediahub/thumbs/`;启动时把全局库数据自动迁移到各自库目录(复制不删除,旧全局库保留兜底);整个素材文件夹拷贝即带走全部元数据/标签/评分/缩略图
- **真实文件夹树**:侧栏「文件夹」按库内素材相对路径动态构建(父子层级、计数、索引目录节点),替换静态演示树;演示模式保留静态树
- **虚拟滚动**:瀑布流(按列分配)/网格/列表三视图虚拟化,只渲染可见窗口;万级库浏览与滚动流畅;与既有缩略图懒生成天然配合
- **索引外部目录**:把任意外部文件夹"索引"进当前库——不复制不移动原文件;索引素材出现在当前库网格,缩略图/调色板同管线生成;监听与缺失标记同样生效;可移除索引(仅去引用);media 协议白名单扩展到索引目录
- **库管理入口**:标题栏「+」下拉——新建库(选目录)/打开已绑定库(列表)/索引目录(选目录挂到当前库)
- 明确排除:打包发布、3D 离屏缩略图、素材物理移动/复制、跨库合并浏览

## Capabilities

### New Capabilities

- `library-portable`:库内 .mediahub 存储、启动迁移、库管理入口(新建/打开/索引)
- `folder-tree`:按真实目录结构动态构建侧栏树(层级/计数/索引节点/演示回退)
- `library-index`:外部目录索引(引用语义、监听、缺失、移除、协议放行)
- `virtual-browse`:三视图虚拟滚动与可见区按需渲染

### Modified Capabilities

- `asset-browser`:数据源要求补入"索引素材与库内素材同视图展示、侧栏文件夹树随库数据动态构建"(与 folder-tree/library-index 互引)
- `app-shell`:「＋新建素材库」按钮升级为「+」下拉菜单(新建/打开/索引入口)
- `thumbnails`:缩略图缓存位置改为库内 .mediahub/thumbs,thumb 协议跨库指纹查找

## Impact

- 依赖新增:`@tanstack/react-virtual`(虚拟化)
- 主进程:db 打开路径改造(每库一 db)、迁移器、索引表与监听、协议白名单
- 渲染层:Grid 三视图虚拟化改造、Sidebar 文件夹树动态构建、标题栏 + 下拉
- 风险面:迁移中断一致性(复制式迁移安全)、瀑布流列虚拟化的高度测量、索引目录路径包含库目录自身的防重叠
