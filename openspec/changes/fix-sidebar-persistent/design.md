# Design

## Context

`sideHidden` 与检查器折叠 `inspHidden` 是对称引入的：`.layout` 上挂 `side-hidden`，把第一列轨道收成 0，面板由 `overflow:hidden` 裁掉。它不在 `openspec/specs/` 的任何 Requirement 里，全树检索 `sideHidden` / `side-hidden` 在 specs 下无结果，也就是说这条能力从一开始就没有规范覆盖。因此本次没有「主 spec 里的旧条文要改」，只有「补一条规范把常驻写成约束」。

## Goals / Non-Goals

- 目标：侧栏在任何启动条件下都可见；不再存在任何收起入口；旧偏好不会把侧栏带成隐藏态。
- 非目标：不动检查器折叠（`inspHidden` 与筛选条的「面板开关」保留）；不改三栏列宽（236px | minmax(0,1fr) | 304px）；不为侧栏新增显隐快捷键。

## Decisions

### 1. 删掉能力，而不是把默认值改成展开

默认值只影响**首次**启动；用户遇到的是已经写进 `uiPrefs` 的收起态，把默认值改成 `false` 对「重启后仍然隐藏」毫无作用。而只要开关还在，这条「下次启动看不见侧栏」的路径就还在。用户的原话是这个侧栏「需要常驻」，因此最短且正确的实现是删除整条链路。

### 2. 旧偏好字段静默忽略，不做迁移清理

`restoreUiPrefs` 是白名单式 `setState`：只写它认识的字段，多余的 `sideHidden` 自动被丢弃。写一次显式迁移要多读一次磁盘状态、多一条迁移失败分支，而收益为零。

### 3. 灯箱里的开关按钮必须一起删

它是唯一入口。入口留在界面上而状态被删掉，会造出「点了没反应」的死控件，比删掉更糟。

### 4. 保留「不要卸载面板」的既有结构

`App.tsx` 里那段注释（折叠时不要把面板从 DOM 卸载，否则列宽过渡没有对手可动画）描述的是检查器折叠，仍然成立，只把 `sideHidden` 那一段模板串去掉。

## Risks / Trade-offs

- 破坏性：灯箱中不能再临时收起侧栏换取更宽的预览。缓解：灯箱自带全屏（`lightboxFullscreen` 切到 `.pv.full`）可覆盖整窗，且它只作用于灯箱遮罩，不改布局列宽。
- `Icons.tsx` 的 `i-panel-l` symbol 变成无人引用（表里其它未使用图标同样保留），按 scope 不动，以免动到共享图标表。
