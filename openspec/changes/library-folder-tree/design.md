## Context

见 `proposal.md`。当前 `Sidebar` 由资产的 `rel_path` 前缀生成目录节点；外部索引扫描会把索引名写入此前缀，因此会在库内目录树中出现不属于库根的节点。启动 UI 还以两个硬编码示例标签和示例素材作为初始状态，真实库会话尚未恢复时会显示虚构数据。目录监听只处理文件事件，空目录的新增或删除不能触发侧栏刷新。

## Goals / Non-Goals

**Goals:**

- 将库模式目录树的节点来源改为当前库根目录的真实目录，复用现有忽略规则排除 `.mediahub`。
- 在真实目录树之外显示只读索引目录树，按索引来源名称和源相对目录层级浏览与筛选素材。
- 已绑定真实库时只恢复真实库标签与素材；没有已保存标签时自动打开第一个已绑定库，不保留示例标签或示例素材。
- 让右侧图标加号在库根创建唯一的 `未命名` 文件夹，并提供 Windows 式已选中、名称全选的内联改名体验；选中文件夹按 F2 进入同一编辑。
- 让库内真实素材可拖到侧栏真实文件夹，目标行确认后移动文件和数据库相对路径。
- 让外部索引素材可拖到侧栏真实文件夹，目标行确认后只更新应用内归属，不改变索引源文件。
- 在应用内或资源管理器中改变目录后，让目录树刷新而不影响素材库、索引源或数据库记录。

**Non-Goals:**

- 不把外部索引目录并入库根目录树，不改变索引素材在网格中的展示。
- 不创建数据库表、不移动外部索引源文件、不提供删除文件夹或批量目录管理；索引素材拖入时只记录应用内文件夹归属。
- 不删除用户的真实库、素材、标签或数据库记录；本次仅删除渲染层的硬编码示例初始状态。
- 不修改 `asset-card-cleanup-marquee` change 涉及的卡片、网格和样式文件。

## Decisions

### 真实目录枚举由主进程提供

新增一个小型目录服务，从已打开素材库的根路径递归读取目录并返回规范化相对路径，使用既有 `isIgnoredDir` 排除 `.mediahub` 和其他扫描时忽略的目录。渲染层仍从已加载素材计算每个真实节点的计数，但只为主进程返回的目录创建节点，因此索引源和陈旧路径不会泄漏进树。

### 索引目录保持只读且单独筛选

渲染层根据已加载索引素材的 `source_index_id` 与 `@index:<id>/` 相对路径构造独立“索引目录”树。来源根节点使用索引名称，子节点使用源目录层级；点击来源或子节点只改变网格筛选，不提供新建、改名、拖放或移动，避免把源目录误认为可写的库内目录。

备选方案是继续从资产路径建树后过滤索引名；它无法展示空目录，也无法可靠判断陈旧路径，故不采用。仅在渲染层维护新建目录的临时状态则不能产生真实文件系统结果，故不采用。

### 创建和改名均通过受限 IPC

预加载层提供目录列举、创建和重命名方法。主进程依据 `libraryId` 解析当前库根，创建时生成 `未命名`、`未命名 (2)` 等尚未存在的名称；改名时仅接受单个目录名，并拒绝空名、路径分隔符、`.`/`..` 和任何解析后逃逸库根的目标。文件系统错误或重名不会修改原目录，调用方显示错误并重新读取目录树。

让渲染层直接访问文件系统既不符合 Electron 隔离边界，也无法验证路径范围，故不采用。

### 侧栏把新建状态放入现有 UI store

库模式保存真实目录相对路径和当前内联编辑节点。刷新活动库时同时读取素材和目录；点击标题右侧的图标按钮后，创建目录、刷新树、切换到对应 `folder:` 导航并标记该节点为编辑中。编辑行使用输入框自动获得焦点并全选文本；Enter 或失焦提交重命名，Escape 退出编辑并保留已创建的默认目录。原底部“新建文件夹”伪按钮移除，避免两个入口和一个无效入口。

局部组件状态也可实现输入框，但创建、刷新和导航已由 store 协调；放进 store 可避免切换库时遗留编辑节点。

### 启动会话只从真实库恢复

移除 UI store 中硬编码的库标签和示例素材初始值。启动时先读取已绑定库，再将持久化标签中仍存在的库恢复为标签；若已绑定库非空但没有可恢复的标签，则打开第一个已绑定库。真实库存在时，不以示例素材或示例文件夹作为加载失败或空标签的回退。

保留“未绑定任何库”的空状态和新建库入口，不将内置示例数据伪装成用户数据。

### 素材拖放只更新正确的归属

卡片拖动携带当前选中的可处理素材 ID；目标文件夹在拖入时高亮，放下后不立即处理，而是在行内显示「移动 N / 归类 N / 取消」。确认 IPC 逐个校验缺失状态和目标路径：库内素材执行磁盘重命名并更新 `rel_path`，索引素材只更新 `folder_path`，保持源文件、`rel_path` 和 `source_index_id` 不变。目标同名时追加 `(2)` 等后缀，不覆盖库内文件。索引重扫通过原有相对路径复用记录，不会因文件夹归类产生重复记录。

拖放序列沿用 DNF 补丁管理器的标准 HTML5 规则：源卡片设置 `effectAllowed=move` 与专用 MIME，目标行校验 MIME、`preventDefault` 后接受 move，drop 时解码完整选中集合。

### 文件夹事件复用现有刷新通道

根目录监听补充目录新增和删除事件，并复用现有 `assets:changed` 刷新活动库。创建或重命名 IPC 成功后也主动刷新，避免等待监听防抖造成新行延迟出现。目录重命名在文件系统层表现为删除与新增，最终树以重新枚举结果为准。

不新增另一套事件通道，因为当前活动库已经监听 `assets:changed` 并能同时重载素材和目录。

## Risks / Trade-offs

- [资源管理器与应用同时改名] → 主进程每次操作重新验证库根边界，遇到不存在或重名时返回错误并刷新，不覆盖文件。
- [递归枚举大型目录树] → 只返回目录路径且复用现有监听刷新；不扫描文件内容或元数据。
- [空文件夹没有素材计数] → 显示计数 0，这是磁盘真实状态而非隐藏该节点。

## Migration Plan

无需迁移。升级后下一次启动或刷新库时，应用从已绑定库恢复真实标签与素材，侧栏从磁盘重新枚举目录；此前由示例数据或资产路径生成的虚拟节点只从界面消失，数据库与素材文件保持不变。
